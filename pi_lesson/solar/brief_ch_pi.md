# 브리프(내용 가이드) — ML 확장판 ML3장 「물까치를 확인하는 라즈베리파이」

독자: 고등학생(피지컬 컴퓨팅 초보). 앞 장(ML2)에서 피코 2 WH로 물까치 탐지기를 만들고, k-NN으로 물까치 후보를 찾아 MP3로 알리고 WAV와 시각을 microSD에 기록해 본 학생
문체: 해요체(~해요, ~예요)로 통일. 기존 교재와 같은 친절한 설명체. 청유("~해 보세요") 남용 금지, 평서 위주
맥락: 웹 교재 한 챕터의 설명 문단. 각 블록 바로 옆에 단계 목록·코드·표가 따로 있으므로 그 내용을 되풀이하지 말고 의미를 풀어 준다
공통 지시: 블록 하나의 출력은 문단 하나. 빈 줄로 나누지 말 것. 우회 표현('~하는 셈이에요') 대신 직접 서술. 은유·의인화·과장 금지. 대시(—)로 문장 잇지 말 것. HTML 태그는 KEEP에 있는 것만 사용

[블록 1] 위치: 챕터 도입 '왜 배우나요?' / 역할: lead
- 사실: 앞 장의 피코 판단은 1차 판정이라 틀릴 수 있어 '물까치 후보'라고 불렀음
- 사실: BirdNET은 코넬 조류학 연구소와 켐니츠 공과대학이 만든 새소리 인식 AI, 6,000종이 넘는 새를 알아봄
- 사실: BirdNET은 피코에서 돌리기에는 너무 무거워서 라즈베리파이 5에서 돌림
- 사실: 이 장에서는 라즈베리파이 5를 새소리 판정 서버로 만들고 두 가지 방법으로 씀. 하나는 피코가 저장한 WAV를 모아서 다시 판정하는 2차 판정, 다른 하나는 피코가 소리를 Wi-Fi로 보내 바로 판정받는 실시간 판정
- KEEP: <b>라즈베리파이 5</b>
- 분량: 4~5문장

[블록 2] 위치: '시작하기 전에' 첫 문단 / 역할: 본문
- 사실: 진행 순서는 라즈베리파이 세팅(부록), 서버 켜기, 2차 판정, 실시간 판정, 세 방식 비교
- 사실: 피코, 라즈베리파이, PC를 모두 교실의 같은 공유기(Wi-Fi)에 연결함
- 사실: 모둠마다 라즈베리파이 한 대를 쓰고, 모둠의 피코는 자기 모둠 라즈베리파이의 주소로 소리를 보냄
- 사실: 라즈베리파이에는 모니터를 연결하지 않고 PC에서 원격으로 접속해 명령을 입력함
- KEEP: <b>같은 공유기</b>
- 분량: 3~4문장

[블록 3] 위치: 콜아웃 '얼마나 잘 맞힐까?' (바로 위에 세 방식의 재현율·오판 표가 있음. 표의 수치는 되풀이하지 말 것) / 역할: 콜아웃
- 사실: 인터넷에 공개된 물까치·다른 새 녹음과 생활 소리를 피코와 같은 3초·16kHz 소리로 바꿔 미리 시험함
- 사실: 피코만 판단하면 물까치를 많이 찾지만 다른 새와 생활 소리도 물까치라고 자주 함
- 사실: BirdNET만 판단하면 찾는 물까치는 줄지만 다른 소리를 물까치라고 하는 일이 거의 없음. 새가 아닌 소리는 한 번도 물까치로 판단하지 않았음
- 사실: 피코가 먼저 거른 뒤 BirdNET에 물으면 오판은 BirdNET만큼 적지만 놓치는 물까치가 더 많음. 피코와 BirdNET이 놓치는 물까치가 서로 다르기 때문
- 사실: 그래서 이 장의 기본 설정은 소리가 나면 모두 BirdNET에 묻는 것
- 사실: BirdNET은 15kHz까지 듣는데 피코의 녹음은 8kHz까지만 담겨 있어, 원래 품질의 녹음보다 잘 못 맞힘
- KEEP: <b>모두 BirdNET에 묻는</b>
- 분량: 5~6문장

[블록 4] 위치: '준비물' 표 아래 / 역할: 본문
- 사실: 표의 링크는 디바이스마트 상품. 가격과 재고는 주문할 때 다시 확인
- 사실: 라즈베리파이 5는 전원이 부족하면 경고를 내고 느려지므로 공식 27W 어댑터를 씀
- 사실: 팬이 달린 공식 케이스를 쓰면 판정을 오래 해도 뜨거워지지 않음
- 사실: 라즈베리파이용 microSD는 운영체제를 담는 카드로, 피코의 녹음용 카드나 MP3용 카드와 다른 카드임
- 사실: 라즈베리파이를 처음 쓴다면 이 장을 시작하기 전에 부록의 세팅을 먼저 끝냄
- KEEP: <b>부록</b>
- 분량: 4~5문장

[블록 5] 위치: '서버 켜기' 첫 문단 / 역할: 본문
- 사실: 서버 프로그램 bird_server.py는 BirdNET을 한 번 불러 두고 판정 요청을 기다림
- 사실: 판정하는 새는 물까치, 까치, 직박구리, 참새, 멧비둘기, 박새, 큰부리까마귀 일곱 종으로 좁혀 둠. 목록을 좁히면 우리 학교에 없는 새로 잘못 판단하는 일이 줄어듦
- 사실: 첫 실행 때 BirdNET 모델을 내려받으므로 인터넷이 필요함
- 사실: 서버가 켜지면 화면에 주소가 나오고, 같은 공유기에 연결된 PC의 브라우저에서 그 주소를 열면 판정 페이지가 나옴
- 사실: 원격 접속 창을 닫으면 서버도 꺼짐. 창을 닫아도 계속 켜 두려면 부록의 자동 실행을 설정함
- KEEP: <code>bird_server.py</code>
- 분량: 4~5문장

[블록 6] 위치: '① 2차 판정' 첫 문단 / 역할: 본문
- 사실: 앞 장의 탐지기가 microSD에 남긴 물까치 후보 WAV를 카드 리더로 PC에 옮긴 뒤, 판정 페이지에서 여러 개를 한꺼번에 올림
- 사실: 표에는 파일마다 BirdNET의 판정, 가장 높은 점수를 받은 새, 신뢰도가 나오고 소리를 다시 들을 수 있음
- 사실: 피코가 물까치 후보라고 한 파일 가운데 BirdNET도 물까치라고 한 비율을 세면 피코 판단이 얼마나 맞았는지 알 수 있음
- 사실: BirdNET도 틀릴 수 있으므로, 두 판정이 다른 파일은 직접 들어 보고 결정함
- 분량: 4~5문장

[블록 7] 위치: '② 실시간 판정' 첫 문단 / 역할: 본문
- 사실: 피코는 소리가 나면 3초를 듣고 k-NN 표 수를 센 뒤, 그 WAV를 Wi-Fi로 라즈베리파이에 보냄
- 사실: BirdNET이 새 이름을 답하면 피코가 그 새의 MP3를 틀고, 답은 피코 표 수와 함께 server.csv에 남음
- 사실: BirdNET이 '모르겠음'이라고 답한 소리는 피코와 라즈베리파이 양쪽에서 지움. 사람 목소리일 수 있기 때문
- 사실: 서버가 꺼져 있거나 응답이 없으면 피코는 멈추지 않고 앞 장처럼 피코 판단만으로 관측을 이어감
- KEEP: <code>server.csv</code>
- 분량: 4~5문장

[블록 8] 위치: 'SEND_ALL' 설명 콜아웃 / 역할: 콜아웃
- 사실: SEND_ALL이 True이면 소리가 날 때마다 모두 보내고, False이면 피코가 물까치 표를 MIN_VOTES 이상 줬을 때만 보냄
- 사실: False로 하면 보내는 횟수가 줄어 피코가 다시 듣기까지 기다리는 시간이 짧아지지만, 미리 한 시험처럼 놓치는 물까치가 늘어남
- 사실: 모둠의 목적(물까치를 하나라도 더 찾기, 잘못 기록하지 않기)에 따라 고름
- KEEP: <code>SEND_ALL</code>
- 분량: 3~4문장

[블록 9] 위치: '③ 세 방식 비교하기' 첫 문단 / 역할: 본문
- 사실: 휴대폰으로 물까치 녹음과 다른 소리를 하나씩 틀어 주고, 무엇을 틀었는지 순서대로 적어 둠
- 사실: 관측이 끝나면 server.csv를 스프레드시트로 열어 truth 열을 만들고, 물까치를 튼 줄에는 1, 나머지에는 0을 적음
- 사실: PC 비교 도구가 피코만, BirdNET만, 피코가 거른 뒤 BirdNET 세 방식의 재현율과 오판을 기준별로 보여 줌
- 사실: 결과를 보고 우리 모둠의 관측 목적에 맞는 방식과 기준을 고르고, 그 이유를 적음
- KEEP: <code>truth</code>
- 분량: 4~5문장

[블록 10] 위치: 콜아웃 '탐구 과제' / 역할: 콜아웃
- 사실: 탐구 1은 서버의 신뢰도 기준(MIN_CONF)을 0.25에서 0.10으로 낮추면 찾는 물까치와 오판이 어떻게 바뀌는지 보는 것
- 사실: 탐구 2는 휴대폰과 마이크 사이 거리를 바꾸며 피코와 BirdNET 가운데 어느 쪽 판정이 더 먼저 흔들리는지 보는 것
- 사실: 탐구 3은 소리를 보내고 답을 받기까지 걸리는 시간을 재고, 그동안 피코가 놓치는 소리가 있는지 확인하는 것
- 사실: 결과는 표로 정리하고 왜 그런지 설명을 붙임
- 분량: 4문장

[블록 11] 위치: '현장에서 쓸 때' 첫 문단 / 역할: 본문
- 사실: 실시간 판정은 피코가 교실 공유기의 Wi-Fi가 닿는 곳에 있을 때만 됨. Wi-Fi가 닿지 않는 곳에서는 앞 장처럼 기록만 하고 나중에 2차 판정을 함
- 사실: 라즈베리파이는 전원 어댑터에 연결해 교실에 두고, 부록의 자동 실행을 설정하면 전원만 켜도 서버가 시작됨
- 사실: 소리는 학교 공유기 안에서만 오가고 인터넷으로 나가지 않음
- 사실: 그래도 사람이 대화하는 곳에는 설치하지 않음. 소리가 날 때마다 3초가 라즈베리파이로 보내지기 때문
- 분량: 4~5문장

[블록 12] 위치: 챕터 끝 '정리' / 역할: 본문
- 사실: 피코는 늘 켜 두고 듣는 역할, 라즈베리파이는 무거운 AI로 판정하는 역할을 나눠 맡음
- 사실: 두 판정의 장단점을 같은 데이터로 비교해 보고 관측 방식을 정하는 것이 이 장의 핵심
- 사실: BirdNET의 판정도 확률이므로 중요한 기록은 사람이 소리를 듣고 확인함
- 사실: 더 나아가려면 녹음 품질을 높이거나(더 높은 샘플링 주파수), 우리 지역과 계절에 맞게 BirdNET의 종 목록을 조정할 수 있음
- 분량: 4문장
