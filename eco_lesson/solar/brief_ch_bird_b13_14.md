# 브리프(내용 가이드) — ML 확장판 3장 「물까치를 찾는 피코」

독자: 고등학생(피지컬 컴퓨팅 초보). 앞 장에서 INMP441 마이크로 소리를 모으고 k-NN으로 분류해 본 학생
문체: 해요체(~해요, ~예요)로 통일. 기존 교재와 같은 친절한 설명체. 청유("~해 보세요") 남용 금지, 평서 위주
맥락: 웹 교재 한 챕터의 설명 문단. 각 블록 바로 옆에 배선도·코드·표가 따로 있으므로 그 내용을 되풀이하지 말고 의미를 풀어 준다
공통 지시: 블록 하나의 출력은 문단 하나. 빈 줄로 나누지 말 것. 우회 표현('~하는 셈이에요') 대신 직접 서술. 은유·의인화·과장 금지. 대시(—)로 문장 잇지 말 것. HTML 태그는 KEEP에 있는 것만 사용

[블록 13] 위치: '③ 채점하고 기준 정하기' 첫 문단 (바로 아래에 단계 목록과 채점 도구가 따로 있음) / 역할: 본문
- 사실: 예시로 쓴 소리로 채점하면 점수가 실제보다 높게 나오므로, 예시로 쓰지 않은 소리를 탐지기에 직접 들려주어 채점함
- 사실: 휴대폰으로 물까치 녹음과 다른 소리를 하나씩 틀고, 무엇을 틀었는지 순서대로 적어 둠
- 사실: 탐지기가 남긴 decisions.csv에는 소리마다 물까치 표 수가 기록되어 있어서, 정답만 적어 두면 탐지기를 다시 돌리지 않고도 MIN_VOTES별 결과를 비교할 수 있음
- 사실: 재현율은 물까치 소리 가운데 물까치라고 한 비율이고, 오판은 다른 소리를 물까치라고 한 비율
- 사실: MIN_VOTES를 올리면 오판은 줄지만 놓치는 물까치가 늘어남. 어디서 멈출지는 관측 목적에 따라 정함
- KEEP: <b>예시로 쓰지 않은 소리</b>
- KEEP: <code>decisions.csv</code>
- 분량: 4~5문장

[블록 14] 위치: 콜아웃 '탐구 과제' / 역할: 콜아웃
- 사실: 탐구 1은 예시를 더 모은 뒤 같은 소리를 다시 들려주고 재현율과 오판이 어떻게 바뀌는지 비교하는 것
- 사실: 탐구 2는 귀뚜라미 같은 곤충 소리를 물까치로 헷갈리는지, 헷갈린다면 어떤 예시를 더해야 하는지 알아보는 것
- 사실: 결과는 표로 정리하고 왜 그런지 설명을 붙임
- 분량: 3문장
