# 브리프(내용 가이드) — ML 확장판 3장 「물까치를 찾는 피코」

독자: 고등학생(피지컬 컴퓨팅 초보). 앞 장에서 INMP441 마이크로 소리를 모으고 k-NN으로 분류해 본 학생
문체: 해요체(~해요, ~예요)로 통일. 기존 교재와 같은 친절한 설명체. 청유("~해 보세요") 남용 금지, 평서 위주
맥락: 웹 교재 한 챕터의 설명 문단. 각 블록 바로 옆에 배선도·코드·표가 따로 있으므로 그 내용을 되풀이하지 말고 의미를 풀어 준다
공통 지시: 블록 하나의 출력은 문단 하나. 빈 줄로 나누지 말 것. 우회 표현('~하는 셈이에요') 대신 직접 서술. 은유·의인화·과장 금지. 대시(—)로 문장 잇지 말 것. HTML 태그는 KEEP에 있는 것만 사용

- 블록 2: KEEP 조각 <b>PC와 USB</b> 가 없었습니다. 그대로 넣으세요.

[블록 1] 위치: 챕터 도입 '왜 배우나요?' / 역할: lead
- 사실: 물까치는 우리나라 학교와 공원 주변에서 흔히 보이는 텃새, 여러 마리가 무리 지어 다니며 거칠고 짧은 소리를 반복함
- 사실: 새소리 앱은 녹음을 짧은 구간으로 나누어 주파수 모양을 비교해 새를 알아봄
- 사실: 이 장에서는 피코가 3초 동안 소리를 듣고, 학생이 직접 모은 예시와 비교해 물까치인지 판단함
- 사실: 물까치 후보를 찾으면 스피커로 알리고, 그 3초와 시각을 기록함
- 사실: 피코의 판단은 1차 판정. 다음 장에서 BirdNET이라는 새소리 AI로 2차 확인을 함
- KEEP: <b>물까치 후보</b>
- 분량: 4~5문장

[블록 2] 위치: '시작하기 전에' 첫 문단 / 역할: 본문
- 사실: 진행 순서는 조립, 부품 확인, 예시 모으기, 탐지기 실행, 채점, 현장 설치
- 사실: 처음에는 PC와 USB로 연결해 전원과 화면(Thonny)을 함께 쓰고, 잘 되면 보조배터리로 바꿔 밖으로 들고 나감
- 사실: 납땜은 하지 않음. 모든 부품은 꽂아서 연결함
- KEEP: <b>PC와 USB</b>
- 분량: 3~4문장

[블록 3] 위치: 콜아웃 '얼마나 잘 맞힐까?' / 역할: 콜아웃
- 사실: 인터넷에 공개된 실제 물까치·다른 새 녹음으로 이 장의 코드와 같은 계산을 미리 시험함
- 사실: 같은 장소에서 모은 예시로 판단한 경우, 물까치 녹음의 79%를 찾았고 다른 소리의 13%를 물까치로 잘못 판단함
- 사실: 다른 장소 녹음으로만 배운 경우, 잘못 판단을 20% 이하로 묶으면 물까치의 62%까지만 찾음
- 사실: 그래서 우리 학교에서 직접 모은 예시가 중요함
- 사실: 피코의 판단은 틀릴 수 있으므로 '물까치다'가 아니라 '물까치 후보'로 부름
- KEEP: <b>직접 모은 예시</b>
- 분량: 4~5문장
