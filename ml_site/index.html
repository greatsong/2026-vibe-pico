소리를 배우는 피코 — 머신러닝 첫걸음

마이크 + k-NN으로 ‘내가 가르친 소리’(휘파람·박수·말소리·문·발걸음…)를 알아맞히는 만능 소리 분류기.

🎯 이 장을 마치면
  • 마이크로 소리를 숫자(특징)로 읽는다
  • 콘솔에서 키를 눌러 ‘내가 고른 소리들’을 직접 라벨링한다
  • k-NN으로 새 소리가 무엇인지 예측한다
  • 정규화·k·확신도·다중클래스 같은 머신러닝 핵심 개념을 이해한다
  • ML이 잘 되는 소리와 헷갈리는 소리의 차이를 안다
💡 왜 배우나요?

음성비서·새 찾기 앱·Shazam은 소리를 어떻게 알아들을까요? 비밀은 소리를 숫자로 바꿔, 닮은 것과 비교하는 거예요. 지금까지 피코는 if 값 > 임계값으로만 판단했지만, 소리는 규칙 한 줄로 못 가릅니다. 그래서 오늘은 다르게 — 내가 보여준 소리 예시만 모으면 피코가 스스로 경계를 찾습니다. 이것이 지도학습이고, 가장 직관적인 k-NN으로 ‘내 손이 만든 미니 음성 AI’를 만듭니다.

준비물
피코 2 WH + 그로브 쉴드, INMP441 전방향 마이크 모듈(핀헤더 납땜형), 점퍼선(암-수) 6가닥, WS2813 LED(2장에서 쓰던 것), USB 케이블. 새로 살 건 마이크와 점퍼선뿐이에요.

걸리는 시간
데이터 모으기 2~3분 + 예측까지, 천천히 해도 넉넉해요.
💡 우리가 쓰는 마이크 — INMP441 전방향 마이크 (I2S 디지털)
이 챕터의 마이크는 INMP441 전방향 MEMS 마이크(핀헤더 납땜형)예요. 소리를 디지털(I2S)로 곧장 보내 줘서 잡음이 적고 음질이 좋습니다. 그로브 케이블이 아니라 점퍼선 6가닥으로 쉴드의 헤더 핀에 연결해요 — 아래 ‘하드웨어 준비’의 회로 구성도를 그대로 따라오면 5분이면 끝나요.

핵심 개념 — 기계가 소리를 배운다는 것

어려운 수학은 없어요. 오늘의 전부는 딱 한 문장 — ‘새 소리와 가장 닮은 이웃에게 물어본다’입니다. 먼저 도구와 개념을 하나씩 살펴봐요.

지도학습
정답(라벨)이 붙은 예시로 배워, 새 데이터의 정답을 맞히는 것. 우리는 소리마다 이름(휘파람·박수…)을 알려줍니다.
k-NN
새 소리와 가장 닮은(가까운) 이웃 k개의 다수결로 결정. k는 ‘몇 명에게 물어볼까’예요.
‘학습’의 정체
k-NN은 훈련이 따로 없어요. 예시를 통째로 기억해뒀다 비교할 뿐. 그래서 모델 = 우리가 모은 데이터입니다.
특징(feature)
소리에서 뽑은 숫자 3개 — 크기(RMS)=얼마나 큰가, 높낮이(ZCR)=얼마나 높은가, 들쭉날쭉(crest)=톡 치는 소리(박수·노크)인가 이어지는 소리(목소리)인가.
🔑 정규화 — 단위가 다르면 공평하지 않다
세 특징의 범위가 제각각이에요. 높낮이는 0~수천, 크기는 0~수만, 들쭉날쭉은 1~수십. 그냥 거리를 재면 숫자가 큰 크기에만 휘둘립니다. 그래서 세 특징을 각각 0~1로 다시 스케일해 공평하게 만들어요. 머신러닝에서 거의 항상 필요한 단계랍니다.
🔬 더 알아보기 — 영교차(ZCR)가 어떻게 ‘높낮이’가 되나요?
소리는 0(가운데)을 중심으로 위아래로 출렁이는 물결이에요. 높은 소리일수록 물결이 빨라서 0을 더 자주 지나갑니다. 그래서 ‘0을 몇 번 지났나(영교차수)’를 세면 음의 높낮이를 대신할 수 있어요. 휘파람은 영교차가 많고, 낮은 ‘우~’ 허밍은 적습니다. FFT 같은 어려운 수학 없이도 음높이를 잡는 똑똑한 꼼수예요.
ℹ️ k 고르기 & 확신도
k=1은 이웃 하나에 휘둘려 과민(과적합), 너무 큰 k는 경계가 흐려져요. 보통 홀수 5. 확신도는 다수 비율 — 이웃 5 중 4가 ‘박수’면 ‘박수, 확신 80%’이고, 이걸 LED 칸 수로 보여줍니다.
ℹ️ 2가지에서 여러 가지로 — 다중클래스
성공/실패 같은 2개만이 아니라, 휘파람·박수·말소리·노크처럼 여러 종류도 똑같이 됩니다. 이웃 k명의 다수결에서 가장 표를 많이 받은 이름이 답이에요. 소리 종류마다 LED 색을 다르게 켭니다.

하드웨어 준비 — INMP441 마이크 연결하기 (회로 구성도)

마이크는 INMP441 전방향 마이크 모듈 하나만 연결하면 됩니다. 그로브 포트가 아니라 쉴드가 뽑아 준 피코 헤더 핀에 점퍼선(암-수) 6가닥으로 꽂아요 — 아래 회로 구성도대로 한 선씩 따라오면 5분이면 끝나요. 결과를 보여줄 LED(2장에서 쓰던 것)는 D16 포트에 그로브 케이블로 꽂으면 됩니다. 아래 인터랙티브 배선표에서 포트·핀을 하나씩 체크하며 따라오세요.

🎙️ INMP441 연결 — 점퍼 6선 · 거의 나란히

⚠️ 먼저! VDD는 반드시 3.3V — 5V 금지
INMP441은 3.3V 소자라 VDD를 5V에 꽂으면 망가집니다. 쉴드가 피코 40핀을 모두 헤더로 뽑아주니, 그 헤더에 점퍼선(암-수)을 꽂으면 돼요. 요령: 신호선 바로 양옆의 GND(23·28번)를 쓰면 23~28번 한 군데에 거의 다 모입니다. 7색 리본선이면 가장자리 ‘흰’선은 안 꽂은 채로 두고(자를 필요 없어요 — 재사용해요) 나머지를 순서대로 꽂으세요. 정작 중요한 건 색이 아니라 신호↔핀 짝이에요 — 다른 선이면 색이 달라도 됩니다.

⚠ 특히 — 리본선을 ‘통째로’ 연속 삽입하지 마세요. 센서 보드는 한 줄이 아니라 2열 6핀이라, 핀 순서가 쉴드 23~28번과 1:1로 맞지 않아요. VDD 한 선만 23~28 묶음과 떨어진 위쪽 36번(3V3)으로 따로 올려야 합니다. 색 순서를 믿지 말고, 아래 핀맵처럼 센서 글자(실크) → 피코 핀 번호를 한 선씩 확인하세요.
🔌 회로 구성도 — VDD만 멀리 36번(3V3)으로!
가로선 5개(GND·SCK·WS·SD·L/R)는 23~28번에 거의 나란히, 회색 VDD만 위쪽 36번(3V3)으로 따로 가요 — 5V에 꽂으면 손상! 점퍼 색은 예시일 뿐, 센서 글자 → 핀이 핵심이에요.

# 소리 인식 ①(I2S) — INMP441 전방향 마이크 값 읽기
# 점퍼 연결: VDD→3.3V(⚠5V 금지), GND→GND, SCK→GP18, WS→GP19, SD→GP20, L/R→GND
from machine import I2S, Pin
import struct, math, time

audio = I2S(0, sck=Pin(18), ws=Pin(19), sd=Pin(20),
            mode=I2S.RX, bits=32, format=I2S.MONO, rate=16000, ibuf=40000)
buf = bytearray(512 * 4)

def level():                       # 짧게 512표본의 '소리 크기'(RMS)
    audio.readinto(buf)
    v = [x >> 16 for x in struct.unpack("<512i", buf)]   # 32→16비트로 줄여 보기 쉽게
    m = sum(v) / 512
    return math.sqrt(sum((x - m) ** 2 for x in v) / 512)

print("준비됐어요! 휘파람·박수·말소리를 내보세요. (Thonny 플로터 추천)")
while True:
    print(level())
    time.sleep(0.05)

따라하기 ① 소리를 잡아 특징 뽑기

소리가 나면 한 덩어리(약 0.2초)로 잡아, 크기(RMS)·높낮이(ZCR)·들쭉날쭉(crest) 세 숫자를 뽑습니다. 이 셋이 다음 단계 예측의 입력이에요.

# 소리 인식 ②(I2S) — INMP441로 소리를 잡아 '특징' 세 개 뽑기
# 크기(RMS) · 높낮이(ZCR) · 들쭉날쭉(crest=peak/RMS)
from machine import I2S, Pin
from neopixel import NeoPixel
import struct, time, math

audio = I2S(0, sck=Pin(18), ws=Pin(19), sd=Pin(20),
            mode=I2S.RX, bits=32, format=I2S.MONO, rate=16000, ibuf=40000)
N = 2400; raw = bytearray(N * 4)
def grab():
    audio.readinto(raw)
    return [x >> 16 for x in struct.unpack("<%di" % N, raw)]
def features(buf):
    n = len(buf); m = sum(buf) / n; ss = 0.0; zc = 0; peak = 0.0; prev = buf[0] - m
    for v in buf:
        d = v - m; ad = d if d >= 0 else -d; ss += d * d
        if ad > peak: peak = ad
        if (d >= 0) != (prev >= 0): zc += 1
        prev = d
    r = math.sqrt(ss / n); return r, zc, peak / (r + 1e-9)
small = bytearray(512 * 4)
def level():
    audio.readinto(small); v = [x >> 16 for x in struct.unpack("<512i", small)]; m = sum(v) / 512
    return math.sqrt(sum((x - m) ** 2 for x in v) / 512)

TIMING = (280, 515, 515, 745); NUM = 10
np = NeoPixel(Pin(16), NUM, timing=TIMING)

# 소리 인식 ③(I2S) — INMP441로 소리 모으기 (콘솔 키 라벨링) · 특징 3개
from machine import I2S, Pin
from neopixel import NeoPixel
import struct, time, math

audio = I2S(0, sck=Pin(18), ws=Pin(19), sd=Pin(20),
            mode=I2S.RX, bits=32, format=I2S.MONO, rate=16000, ibuf=40000)
N = 2400; raw = bytearray(N * 4)
def grab():
    audio.readinto(raw)
    return [x >> 16 for x in struct.unpack("<%di" % N, raw)]
def features(buf):
    n = len(buf); m = sum(buf) / n; ss = 0.0; zc = 0; peak = 0.0; prev = buf[0] - m
    for v in buf:
        d = v - m; ad = d if d >= 0 else -d; ss += d * d
        if ad > peak: peak = ad
        if (d >= 0) != (prev >= 0): zc += 1
        prev = d
    r = math.sqrt(ss / n); return r, zc, peak / (r + 1e-9)
small = bytearray(512 * 4)
def level():
    audio.readinto(small); v = [x >> 16 for x in struct.unpack("<512i", small)]; m = sum(v) / 512
    return math.sqrt(sum((x - m) ** 2 for x in v) / 512)

TIMING = (280, 515, 515, 745); NUM = 10
np = NeoPixel(Pin(16), NUM, timing=TIMING)
def flash(c, t=0.2): np.fill(c); np.write(); time.sleep(t); np.fill((0, 0, 0)); np.write()

    for ln in open("sounds.csv"):

        if ln == "" or ln.startswith("rms"): continue
        nm = ln.split(",")[3]; c[nm] = c.get(nm, 0) + 1

for k, v in LABELS.items(): print("  %s = %s" % (k, v))

    best = None; bestr = -1.0; t0 = time.ticks_ms()
    while time.ticks_diff(time.ticks_ms(), t0) < 3000:

    rms, zcr, crest = best

    flash((0, 40, 0))
    print("  저장! %s (크기=%.0f 높낮이=%d 들쭉=%.2f) | 현재: %s" % (name, rms, zcr, crest, counts()))
    time.sleep(0.3)
print("끝! sounds.csv 저장됨:", counts())

# 소리 인식 ④(I2S) — INMP441 + k-NN(다수결)으로 알아맞히기 + LED · 특징 3개
import struct, time, math
from machine import I2S, Pin
from neopixel import NeoPixel

audio = I2S(0, sck=Pin(18), ws=Pin(19), sd=Pin(20),
            mode=I2S.RX, bits=32, format=I2S.MONO, rate=16000, ibuf=40000)
N = 2400; raw = bytearray(N * 4)
def grab():
    audio.readinto(raw)
    return [x >> 16 for x in struct.unpack("<%di" % N, raw)]
def features(buf):
    n = len(buf); m = sum(buf) / n; ss = 0.0; zc = 0; peak = 0.0; prev = buf[0] - m
    for v in buf:
        d = v - m; ad = d if d >= 0 else -d; ss += d * d
        if ad > peak: peak = ad
        if (d >= 0) != (prev >= 0): zc += 1
        prev = d
    r = math.sqrt(ss / n); return r, zc, peak / (r + 1e-9)
small = bytearray(512 * 4)
def level():
    audio.readinto(small); v = [x >> 16 for x in struct.unpack("<512i", small)]; m = sum(v) / 512
    return math.sqrt(sum((x - m) ** 2 for x in v) / 512)

TIMING = (280, 515, 515, 745); NUM = 10
np = NeoPixel(Pin(16), NUM, timing=TIMING)
PALETTE = [(40, 0, 0), (0, 40, 0), (0, 0, 40), (40, 40, 0), (40, 0, 40), (0, 40, 40)]
def show(ci, lv):
    c = PALETTE[ci % len(PALETTE)]
    for i in range(NUM): np[i] = c if i < lv else (0, 0, 0)
    np.write()

rows = []
for ln in open("sounds.csv"):
    ln = ln.strip()
    if ln == "" or ln.startswith("rms"): continue
    r, z, c, nm = ln.split(","); rows.append((float(r), float(z), float(c), nm))
names = sorted(set(r[3] for r in rows)); cidx = {nm: i for i, nm in enumerate(names)}
print("예시 %d개, 소리 종류: %s" % (len(rows), names))
mins = [min(r[i] for r in rows) for i in range(3)]
maxs = [max(r[i] for r in rows) for i in range(3)]
def norm(v): return [(v[i] - mins[i]) / (maxs[i] - mins[i] + 1e-9) for i in range(3)]
ex = [(norm(r[:3]), r[3]) for r in rows]
def predict(feat, k=5):
    q = norm(feat)
    def d2(e): return sum((e[0][i] - q[i]) ** 2 for i in range(3))
    near = sorted(ex, key=d2)[:k]; vote = {}
    for e in near: vote[e[1]] = vote.get(e[1], 0) + 1
    b = max(vote, key=vote.get); return b, vote[b] / sum(vote.values())

print("조용히… 배경소음 측정 중")
for _ in range(8): level()                              # I2S는 켜진 직후 값이 튀어요 → 워밍업으로 버림

THRESH = base * 2 + 20   # 예측이 안 뜨면 2→1.5로↓, 너무 잦으면 ↑ (max()는 한 번 튀면 영영 안 떠요)
print("준비! 소리를 내면 알아맞힐게요.")
while True:
    if level() > THRESH:
        feat = features(grab()); name, conf = predict(feat)
        print("이건… %s!  (확신 %d%%, 크기=%.0f 높낮이=%d 들쭉=%.2f)"
              % (name, conf * 100, feat[0], feat[1], feat[2]))
        show(cidx[name], max(1, int(conf * NUM))); time.sleep(1.0); show(0, 0)

# 소리 인식 ⑤ (심화 · INMP441) — FFT 주파수밴드 특징으로 더 똑똑하게
# 8개 주파수 대역의 에너지를 특징으로 쓰면 '음색(timbre)'까지 구분해요.
# ulab 없이 Goertzel 알고리즘으로 각 대역 에너지를 직접 계산합니다.
# 한 번 실행에서 [수집] → 'go' 입력 → [예측] 흐름으로 끝납니다.
from machine import I2S, Pin
from neopixel import NeoPixel
import struct, time, math

audio = I2S(0, sck=Pin(18), ws=Pin(19), sd=Pin(20),
            mode=I2S.RX, bits=32, format=I2S.MONO, rate=16000, ibuf=40000)
N = 1600; raw = bytearray(N * 4)
def grab():
    audio.readinto(raw)
    return [x >> 16 for x in struct.unpack("<%di" % N, raw)]

BANDS = [200, 350, 600, 1000, 1700, 2800, 4500, 7000]   # 8개 대역 중심 주파수(Hz)
def goertzel(x, f):                 # 특정 주파수 f의 에너지(파워)
    k = 2 * math.cos(2 * math.pi * f / 16000); s1 = 0.0; s2 = 0.0
    for v in x:
        s0 = v + k * s1 - s2; s2 = s1; s1 = s0
    return s1 * s1 + s2 * s2 - k * s1 * s2
def features(x):                    # 음량과 무관한 '스펙트럼 모양' 8개
    m = sum(x) / len(x); x = [v - m for v in x]
    e = [max(goertzel(x, f), 0.0) for f in BANDS]; tot = sum(e) + 1e-9
    return [math.log(ei / tot + 1e-6) for ei in e]

small = bytearray(512 * 4)
def level():
    audio.readinto(small); v = [x >> 16 for x in struct.unpack("<512i", small)]; m = sum(v) / 512
    return math.sqrt(sum((x - m) ** 2 for x in v) / 512)

TIMING = (280, 515, 515, 745); NUM = 10
np = NeoPixel(Pin(16), NUM, timing=TIMING)
PALETTE = [(40, 0, 0), (0, 40, 0), (0, 0, 40), (40, 40, 0), (40, 0, 40), (0, 40, 40)]
def show(ci, lv):
    c = PALETTE[ci % len(PALETTE)]
    for i in range(NUM): np[i] = c if i < lv else (0, 0, 0)
    np.write()

# ★ 음색이 다른 소리일수록 효과 큼 (예: 휘파람 vs 쉬익, 모음 '아' vs '이') ★
LABELS = {"1": "휘파람", "2": "말소리", "3": "노크", "4": "박수"}
D = len(BANDS)
print("조용히… 배경소음 측정 중")
for _ in range(8): level()                              # I2S는 켜진 직후 값이 튀어요 → 워밍업으로 버림
bg = sorted(level() for _ in range(25)); base = bg[len(bg) // 2]   # 중앙값(튀는 값에 안 휘둘림)
THRESH = base * 2.5 + 25   # 예측이 안 뜨면 ↓, 너무 잦으면 ↑

data = []
print("\n[수집] 숫자키 누르고 소리내기 · go=예측 시작")
for k, v in LABELS.items(): print("  %s = %s" % (k, v))
while True:
    cmd = input("라벨(go=예측)> ").strip()
    if cmd == "go": break
    nm = LABELS.get(cmd)
    if not nm: continue
    print("  ▶ '%s' 소리를 지금 내세요… (3초)" % nm)
    best = None; bestr = -1.0; t0 = time.ticks_ms()
    while time.ticks_diff(time.ticks_ms(), t0) < 3000:        # 3초 중 '가장 또렷한' 조각
        x = grab(); mm = sum(x) / len(x); rr = sum((v - mm) ** 2 for v in x)
        if rr > bestr: bestr = rr; best = features(x)
    data.append((best, nm)); print("  저장 (총 %d개)" % len(data))

names = sorted(set(d[1] for d in data)); cidx = {n: i for i, n in enumerate(names)}
mins = [min(d[0][i] for d in data) for i in range(D)]
maxs = [max(d[0][i] for d in data) for i in range(D)]
def norm(f): return [(f[i] - mins[i]) / (maxs[i] - mins[i] + 1e-9) for i in range(D)]
ex = [(norm(d[0]), d[1]) for d in data]
def predict(f, k=5):
    q = norm(f)
    def d2(e): return sum((e[0][i] - q[i]) ** 2 for i in range(D))
    near = sorted(ex, key=d2)[:k]; vote = {}
    for e in near: vote[e[1]] = vote.get(e[1], 0) + 1
    b = max(vote, key=vote.get); return b, vote[b] / sum(vote.values())

print("\n[예측] 소리를 내보세요.")
while True:
    if level() > THRESH:
        nm, conf = predict(features(grab()))
        print("이건… %s!  (확신 %d%%)" % (nm, conf * 100))
        show(cidx[nm], max(1, int(conf * NUM))); time.sleep(1.0); show(0, 0)

특징 2개(0.73) → 3개(0.96) → FFT 8밴드는 음색이 비슷한 소리까지 잡아냅니다. INMP441의 깨끗한 16kHz 디지털 소리 덕에 피코에서도 잘 돌아가요. ‘성능 = 좋은 특징’임을 몸으로 확인하는 코너.

동작을 배우는 피코 — 머신러닝 첫걸음

Grove 6축 IMU + k-NN으로 ‘물통 세우기(bottle flip)’ 성공을 예측하는 지도학습 첫걸음.

🎯 이 장을 마치면
  • IMU(가속도·자이로)로 동작을 숫자로 읽는다
  • 짝 활동으로 성공/실패 데이터를 모은다(라벨링)
  • k-NN으로 새 동작의 결과를 예측한다
  • 정규화·k·확신도 같은 머신러닝 핵심 개념을 이해한다
  • ML이 잘 되는 문제와 어려운 문제의 차이를 안다
💡 왜 배우나요?

소리 챕터에서 피코는 소리를 배웠어요. 이번엔 몸의 동작(뒤집기·흔들기·던지기) 차례입니다. 짝과 함께 모은 성공/실패 데이터만 보여주면, 피코가 스스로 두 무리의 경계를 찾습니다. 규칙은 한 줄도 안 짭니다. 이것이 지도학습이고, 오늘은 소리 챕터에서 익힌 k-NN으로 ‘물통 세우기(bottle flip)’ 성공을 예측합니다. 핵심은 이번에도 데이터로 배우는 경험이에요.

핵심 개념 — 기계가 배운다는 것

지도학습·k-NN·정규화는 소리 챕터에서 만난 개념이에요. 이미 배웠다면 가볍게 복습하고, 처음이라면 여기서 익혀도 충분합니다. 어려운 수학은 없습니다 — ‘가장 닮은 이웃에게 물어본다’가 전부예요.

지도학습
정답(라벨)이 붙은 예시로 배워, 새 데이터의 정답을 맞히는 것. 우리는 플립마다 성공/실패를 알려줍니다.
k-NN
새 동작과 가장 닮은(가까운) 이웃 k개의 다수결로 결정. k는 ‘몇 명에게 물어볼까’예요.
‘학습’의 정체
k-NN은 훈련이 따로 없어요. 예시를 통째로 기억해뒀다 비교할 뿐. 그래서 모델 = 우리가 모은 데이터입니다.
거리(distance)
두 동작이 얼마나 닮았나 = 두 점 사이 거리(피타고라스). 가까울수록 닮은 동작.
🔑 정규화 — 단위가 다르면 공평하지 않다
두 특징의 범위가 너무 달라요. 회전피크는 0~2000°/s, 가속피크는 0~16g. 그냥 거리를 재면 숫자가 큰 회전에만 휘둘리고 가속은 무시됩니다. 그래서 두 특징을 각각 0~1로 다시 스케일해 공평하게 만들어요. 머신러닝에서 거의 항상 필요한 단계랍니다.
🔬 더 알아보기 — 정규화를 숫자로 — 왜 가속이 무시될까
회전은 100 차이가 흔하지만, 가속은 최대 16이라 100 차이가 아예 불가능합니다. 거리 = √((회전차)²+(가속차)²) 에서 회전차는 수백까지 커지고 가속차는 기껏 몇이라, 제곱하면 가속차는 사실상 0으로 묻혀요. 두 특징을 0~1로 맞추면 ‘회전 0.1 차이 = 가속 0.1 차이’가 되어 둘 다 똑같이 중요해집니다.
ℹ️ k 고르기 & 확신도
k=1은 이웃 하나에 휘둘려 과민(과적합), 너무 큰 k는 경계가 흐려져요. 보통 홀수 5(동점 방지). 확신도는 다수 비율 — 이웃 5 중 4가 성공이면 ‘성공, 확신 80%’이고, 이걸 LED 칸 수로 보여줍니다.

하드웨어 준비 + 값 읽기

Grove 6축 가속도·자이로(LSM6DS3)를 쉴드의 UART1 포트(GP4·GP5 — 이 핀들을 I2C로 씁니다. 실크에 I2C라 적힌 포트가 아니에요!)에 톡 꽂으세요. MQ-2(A0)·LED(D16)는 그대로 둔 채 동시에 쓸 수 있어요.

# 동작 인식 ① — IMU(LSM6DS3) 값 읽기 (외부 라이브러리 없이 복사-실행)
# Grove 6축 가속도·자이로를 쉴드의 UART1 포트(GP4/GP5)에 꽂으세요. (I2C0/I2C1 포트 아님!)
from machine import I2C, Pin
import time, struct

# ── LSM6DS3 레지스터 (ST 데이터시트) ──
WHO_AM_I, CTRL1_XL, CTRL2_G = 0x0F, 0x10, 0x11
OUTX_L_G, OUTX_L_XL = 0x22, 0x28          # 자이로/가속도 출력(각 6바이트: X,Y,Z)

i2c = I2C(0, sda=Pin(4), scl=Pin(5), freq=400000)   # 쉴드 UART1 포트의 GP4/GP5를 I2C로 사용

# 주소 자동 찾기 (그로브 모듈은 0x6A 또는 0x6B)
ADDR = None
for a in (0x6A, 0x6B):
    try:
        if i2c.readfrom_mem(a, WHO_AM_I, 1)[0] in (0x69, 0x6A):   # LSM6DS3 / TR-C
            ADDR = a

rows = []
for ln in open("flips.csv"):

    if ln == "" or ln.startswith("peak_g"): continue
    pg, pa, lab = ln.split(",")

# ── 2) 정규화 준비 (★ 두 특징을 0~1로, 공평하게) ──
g_min = min(r[0] for r in rows); g_max = max(r[0] for r in rows)
a_min = min(r[1] for r in rows); a_max = max(r[1] for r in rows)
def norm(pg, pa):
    ng = (pg - g_min) / (g_max - g_min + 1e-9)
    na = (pa - a_min) / (a_max - a_min + 1e-9)
    return ng, na
examples = [(*norm(r[0], r[1]), r[2]) for r in rows]   # (정규화회전, 정규화가속, 라벨)

# ── 3) k-NN 예측 ──
def predict(pg, pa, k=5):
    ng, na = norm(pg, pa)
    near = sorted(examples, key=lambda e: (e[0]-ng)**2 + (e[1]-na)**2)[:k]
    win = sum(e[2] for e in near)          # 성공(1)에 투표한 이웃 수
    label = 1 if win > k/2 else 0
    conf = max(win, k-win) / k             # 다수쪽 비율 = 확신도
    return label, conf

스스로 점검하기

k-NN에서 ‘학습’은 무엇을 하는 건가요?
훈련이 따로 없고, 예시를 기억해뒀다 새 데이터와 비교합니다. 모델 = 데이터.
정규화는 왜 필요할까요?
회전(0~2000)과 가속(0~16)의 범위가 달라, 안 하면 가속이 무시됩니다. 0~1로 맞춰 공평하게.
k=1과 k=7의 차이는?
k=1은 이웃 하나에 휘둘려 과민(과적합), k가 크면 경계가 부드러워집니다.
확신 80%는 무슨 뜻인가요?
가까운 이웃 5개 중 4개가 같은 답을 냈다는 뜻.
사람이 바뀌면 왜 정확도가 떨어지나요?
손목 동작 폼이 사람마다 달라서. 자기 데이터로 다시 학습(개인화)하면 올라갑니다.
