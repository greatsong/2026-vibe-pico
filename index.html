0.3 · 하드웨어 조립

그로브 베이스 쉴드는 피코 위에 ‘덮어 끼우는’ 확장 보드예요. 센서를 납땜 없이 케이블로 톡 꽂을 수 있게 해 줍니다. 아래 그림처럼 연결합니다.

  1. 피코를 그로브 쉴드에 꽂기핀 방향을 맞춰 피코를 쉴드에 끝까지 눌러 끼웁니다. USB 단자가 쉴드 바깥쪽을 향하도록 방향을 확인하세요. 한 줄이라도 핀이 어긋나면 안 됩니다.
  2. LED 바 → D16 포트WS2813 LED 바의 그로브 케이블을 쉴드의 D16 포트에 꽂습니다. (코드에서는 GP16)
  3. MQ-2 센서 → A0 포트MQ-2 가스센서의 그로브 케이블을 쉴드의 A0 포트에 꽂습니다. (코드에서는 GP26 / ADC0)
  4. USB로 컴퓨터에 연결USB 케이블로 피코와 컴퓨터를 연결합니다. (펌웨어를 처음 설치할 때는 0.4의 BOOTSEL 순서를 따르세요)
⚠️ 꽂는 위치를 헷갈리지 마세요
D16(디지털)과 A0(아날로그)는 쓰임이 다릅니다. LED는 D16, 가스센서는 A0. 반대로 꽂으면 값이 이상하거나 LED가 안 켜져요.

🔬 더 알아보기 — 펌웨어? MicroPython? BOOTSEL? — 용어 정리
펌웨어(firmware)는 어떤 기기를 켰을 때 가장 먼저 돌아가는 ‘기본 소프트웨어’예요. 컴퓨터의 운영체제(윈도우·macOS)에 해당하는, 피코의 속살이라고 보면 됩니다.

MicroPython은 피코 같은 작은 컴퓨터(마이크로컨트롤러)에서 돌아가도록 만든 파이썬이에요. 이 펌웨어를 설치하면, 그때부터 피코가 우리가 쓴 파이썬 코드를 알아듣습니다. (C/C++로도 쓸 수 있지만, 파이썬이 가장 쉬워요.)

BOOTSEL 버튼은 피코를 ‘펌웨어를 새로 받을 준비(부트로더) 모드’로 켜는 버튼이에요. 이 버튼을 누른 채 USB를 꽂으면 컴퓨터에 USB 드라이브처럼 나타나고, 거기에 .uf2 파일을 끌어다 놓으면 설치됩니다.

.uf2는 이런 보드에 드래그&드롭으로 펌웨어를 넣도록 만든 파일 형식(USB Flashing Format)입니다.
❌ RP2350 드라이브가 안 나타남
원인BOOTSEL 버튼을 누르지 않고 꽂았거나, 충전 전용 케이블입니다.
해결케이블을 뽑고 → BOOTSEL 버튼을 누른 채 다시 꽂으세요. 그래도 안 되면 데이터용 케이블로 교체합니다.

CHAPTER 01

와이파이 센서 대시보드

피코를 와이파이에 연결하고, 신호 세기(RSSI)를 스마트폰 브라우저에서 실시간 그래프로 봅니다. 첫 IoT 작품이에요.

🎯 이 장을 마치면
  • 피코를 와이파이(STA 모드)에 연결할 수 있다
  • 신호 세기(RSSI)가 무엇이고 어떻게 읽는지 안다
  • 피코를 작은 웹서버로 만들어 브라우저에서 데이터를 본다
  • ‘피코는 /data로 값만 주고, 그래프는 브라우저가 그린다’는 구조를 이해한다
💡 왜 배우나요?

센서 값을 셸에서만 보면 나만 볼 수 있죠. 하지만 피코가 웹서버가 되면, 같은 와이파이에 있는 누구나 스마트폰으로 실시간 값을 볼 수 있어요. 이 장에서 익히는 ‘피코=서버, 브라우저=화면’ 구조는 뒤의 날씨·가스 대시보드에서도 똑같이 재사용됩니다.

핵심 개념

STA 모드
피코가 집/학교 와이파이에 접속하는 모드. network.WLAN(network.STA_IF)
RSSI
신호 세기. 단위는 dBm이고 음수예요. -50처럼 0에 가까울수록 강하고, -80처럼 작을수록 약합니다.
소켓 웹서버
포트 80에서 브라우저의 접속을 기다리다가, 요청이 오면 HTML이나 데이터를 돌려주는 작은 서버.
/data 폴링
브라우저가 1초마다 /data를 불러 최신 값을 받고, Chart.js로 그래프를 갱신하는 방식.
🔬 더 알아보기 — RSSI는 왜 -50, -80처럼 ‘음수’일까? (dBm과 데시벨)
RSSI(Received Signal Strength Indicator)의 단위 dBm은 ‘1밀리와트(mW)에 견준 신호 세기를 데시벨로 나타낸 값’이에요. 정의상 0 dBm = 1 mW입니다.

와이파이 신호가 안테나에 도달할 때의 전력은 1 mW보다 훨씬 작아서(보통 1mW의 수만분의 1 ~ 1억분의 1 수준), 로그(데시벨)로 바꾸면 음수가 됩니다. 그래서 값이 항상 마이너스예요.
· -30 dBm ≈ 아주 강함(공유기 바로 옆)
· -67 dBm ≈ 영상통화도 무난
· -80 dBm ≈ 약함, 끊길 수 있음

데시벨은 로그 스케일이라, 10 dB 차이가 전력 10배 차이예요. 즉 -60에서 -70으로 떨어지면 신호 전력이 1/10로 준 겁니다. 숫자 차이는 작아 보여도 체감 차이가 큰 이유죠.

따라하기

Step 1. 주변에 어떤 와이파이가 있는지 스캔해 봅니다. (셸에서 실행)

Step 1 · 와이파이 스캔PYTHON
# 주변에 어떤 와이파이가 있는지 스캔해 봅니다
import network

wlan = network.WLAN(network.STA_IF)   # STA = 와이파이에 '접속하는' 모드
wlan.active(True)

for net in wlan.scan():
    ssid = net[0].decode()            # 와이파이 이름
    rssi = net[3]                     # 신호 세기 (dBm, 0에 가까울수록 강함)
    print("%-22s  %d dBm" % (ssid, rssi))

핵심 개념 — timing이 진짜 중요해요

🔑 WS2813은 timing 인자가 필수
우리가 쓰는 LED는 WS2813 계열이라, MicroPython NeoPixel의 기본 타이밍과 안 맞습니다. 그대로 두면 색이 깨지거나 엉뚱한 칸이 켜져요. 그래서 반드시 이렇게 만듭니다:

🔬 더 알아보기 — timing=(280, 515, 515, 745)의 정체 (1선 통신과 GRB)
WS2813 같은 LED는 칸이 10개여도 데이터 선이 하나뿐이에요. 그래서 0과 1을 ‘펄스(전기 신호)의 길이’로 구분합니다. 이게 1-wire(원-와이어) 프로토콜이에요.

네 숫자는 나노초(ns, 10억분의 1초) 단위의 시간이고, 각각:
· T0H=280 — ‘0’을 보낼 때 켜 두는 시간
· T0L=515 — ‘0’을 보낼 때 꺼 두는 시간
· T1H=515 — ‘1’을 보낼 때 켜 두는 시간
· T1L=745 — ‘1’을 보낼 때 꺼 두는 시간

이 길이가 칩이 기대하는 값과 안 맞으면 0을 1로, 1을 0으로 잘못 읽어 색이 깨집니다. 칩 종류마다 기대 시간이 조금씩 달라, WS2813엔 이 네 값을 직접 지정해 주는 거예요.

또 하나, 사람은 색을 (빨강, 초록, 파랑) = RGB 순서로 생각하지만 이 LED는 내부적으로 GRB(초록·빨강·파랑) 순서로 데이터를 받습니다. 대부분의 펌웨어에서는 (r, g, b)로 쓰면 되지만, 혹시 빨강·초록이 바뀌어 보이면 순서를 조정하면 돼요.

def hsv_to_rgb(h, s, v):
    c = v * s
    x = c * (1 - abs((h / 60) % 2 - 1))
    m = v - c
    if   h < 60:  r, g, b = c, x, 0
    elif h < 120: r, g, b = x, c, 0
    elif h < 180: r, g, b = 0, c, x
    elif h < 240: r, g, b = 0, x, c
    elif h < 300: r, g, b = x, 0, c
    else:         r, g, b = c, 0, x
    return (int((r + m) * 255), int((g + m) * 255), int((b + m) * 255))

for i in range(NUM):

def http_get_json(host, path):
    gc.collect()
    addr = socket.getaddrinfo(host, 443)[0][-1]
    s = socket.socket()
    s.connect(addr)
    try:
        ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT)
        ctx.verify_mode = ssl.CERT_NONE          # 피코엔 인증서 목록이 없어 검증 생략
        s = ctx.wrap_socket(s, server_hostname=host)
    except AttributeError:                       # 옛 펌웨어 호환
        s = ssl.wrap_socket(s, server_hostname=host)
    s.write(("GET %s HTTP/1.0\r\nHost: %s\r\nConnection: close\r\n\r\n"
             % (path, host)).encode())
    buf = b""
    while True:
        chunk = s.read(512)
        if not chunk:
            break
        buf += chunk
    s.close()
    body = buf.split(b"\r\n\r\n", 1)[1]          # 헤더 떼고 본문(JSON)만
    return json.loads(body)

from neopixel import NeoPixel

HOST = "api.open-meteo.com"

# 강수확률 단계 → LED 색(rgb). 웹 범례 색·의미와 똑같이 맞춰 둡니다.
#   0~20 맑음(연초록) · 20~50 흐림(노랑) · 50~80 비 가능(파랑) · 80~ 비 확실(보라)
LEVELS = [(20, (0, 30, 5)), (50, (30, 25, 0)), (80, (0, 10, 40)), (101, (15, 0, 40))]

state = {"probs": [None] * 24, "date": "", "fetched": None}


def level_index(p):
    p = p if p is not None else 0
    for i, (thr, _rgb) in enumerate(LEVELS):
        if p < thr:
            return i
    return len(LEVELS) - 1


def connect_wifi():
    wlan = network.WLAN(network.STA_IF)
    wlan.active(True)
    wlan.connect(SSID, PASSWORD)
    print("Wi-Fi 연결 중", end="")
    timeout = 20
    while not wlan.isconnected() and timeout > 0:
        print(".", end=""); time.sleep(0.5); timeout -= 1
    if wlan.isconnected():
        ip = wlan.ifconfig()[0]
        print("\n✅ 연결 완료!  IP:", ip)
        return ip
    print("\n❌ Wi-Fi 연결 실패")
    return None


def http_get_json(host, path):
    gc.collect()
    addr = socket.getaddrinfo(host, 443)[0][-1]
    s = socket.socket()
    s.connect(addr)
    try:
        ctx = ssl.SSLContext(ssl.PROTOCOL_TLS_CLIENT)
        ctx.verify_mode = ssl.CERT_NONE          # 피코엔 인증서 목록이 없어 검증 생략
        s = ctx.wrap_socket(s, server_hostname=host)
    except AttributeError:                       # 옛 펌웨어 호환
        s = ssl.wrap_socket(s, server_hostname=host)
    s.write(("GET %s HTTP/1.0\r\nHost: %s\r\nConnection: close\r\n\r\n"
             % (path, host)).encode())
    buf = b""
    while True:
        chunk = s.read(512)
        if not chunk:
            break
        buf += chunk
    s.close()
    return json.loads(buf.split(b"\r\n\r\n", 1)[1])


def refresh():
    path = ("/v1/forecast?latitude=%s&longitude=%s"
            "&hourly=precipitation_probability"
            "&timezone=Asia%%2FSeoul&forecast_days=1" % (LAT, LON))
    hourly = http_get_json(HOST, path)["hourly"]
    state["probs"] = hourly["precipitation_probability"]   # 24개 (0~23시)
    state["date"] = hourly["time"][0][:10]                 # "YYYY-MM-DD"
    state["fetched"] = time.ticks_ms()
    for i, h in enumerate(HOURS):                          # LED 갱신
        np[i] = LEVELS[level_index(state["probs"][h])][1]
    np.write()
    print("날씨 갱신:", state["date"])


def refresh_if_due():
    if (state["fetched"] is None or
            time.ticks_diff(time.ticks_ms(), state["fetched"]) > REFRESH * 1000):
        try:
            refresh()
        except Exception as e:
            print("갱신 오류:", e)


def data_json():
    p = state["probs"]
    ago = 0 if state["fetched"] is None else \
        time.ticks_diff(time.ticks_ms(), state["fetched"]) // 1000
    leds = [{"h": h, "p": p[h], "lv": level_index(p[h])} for h in HOURS]
    hourly = [{"h": h, "p": p[h], "lv": level_index(p[h])} for h in range(6, 24)]
    return json.dumps({"date": state["date"], "ago": ago,
                       "leds": leds, "hourly": hourly})

def send_response(conn, status, content_type, body):
    header = ("HTTP/1.1 %s\r\nContent-Type: %s\r\nContent-Length: %d\r\n"
              "Access-Control-Allow-Origin: *\r\nConnection: close\r\n\r\n"
              % (status, content_type, len(body))).encode()
    conn.sendall(header + body)


def run_server():
    addr = socket.getaddrinfo("0.0.0.0", 80)[0][-1]
    srv = socket.socket()
    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    srv.bind(addr)
    srv.listen(3)
    srv.settimeout(REFRESH)        # 방문자가 없어도 주기적으로 깨어나 날씨를 갱신
    print("대시보드 열림 — 위 주소로 접속하세요 (Ctrl+C로 종료)")
    while True:
        refresh_if_due()
        try:
            conn, _ = srv.accept()
        except OSError:            # accept 타임아웃 → 위로 올라가 날씨 갱신
            continue
        try:
            req = conn.recv(512).decode("utf-8", "ignore")
            if "GET /data" in req:
                send_response(conn, "200 OK", "application/json", data_json().encode())
            else:
                send_response(conn, "200 OK", "text/html; charset=utf-8", HTML)
        except Exception as e:
            print("요청 처리 오류:", e)
        finally:
            conn.close()

Open-Meteo 자세히 알기

Open-Meteo는 독일의 비영리 프로젝트로, 여러 나라 기상청의 공개 수치예보 모델을 모아 누구나 쓸 수 있게 제공합니다. API 키도, 회원가입도 필요 없고, 비상업·교육용은 자유롭게 쓸 수 있어요. 주소(URL) 하나에 ‘어디(위도·경도)·무엇(변수)·언제(기간)’를 적어 보내면, 그 자리에서 JSON으로 답을 줍니다.

여러 종류의 API
forecast(예보) · archive(1940년~ 과거 데이터) · air-quality(대기질) · marine(파고·해양) · elevation(고도). 주소의 앞부분만 바꾸면 됩니다.
고를 수 있는 변수
기온 temperature_2m · 습도 relative_humidity_2m · 강수확률 precipitation_probability · 풍속 windspeed_10m · 기압 surface_pressure · 자외선 uv_index · 일사량 shortwave_radiation
응답(JSON) 구조
hourly.time(시각 배열)과 hourly.기온(값 배열)이 같은 순서로 짝을 이룹니다. 그래서 값[6]이 곧 그 날 6시 값이에요.
기간 고르기
forecast_days=1(오늘) · past_days=7(지난 일주일) · archive는 start_date/end_date로 특정 기간.
🔬 더 알아보기 — ‘강수확률 60%’가 실제로 뜻하는 것
강수확률(POP, Probability of Precipitation)은 그 시간·그 지역에 0.1mm 이상의 비가 내릴 통계적 확률입니다. 비의 ‘양’이나 ‘세기’가 아니라 ‘올지 안 올지의 가능성’이에요.

흔한 오해 두 가지:
· ‘60%’는 ‘하늘의 60%에 비가 온다’는 뜻이 아니에요.
· ‘비가 60% 세기로 온다’는 뜻도 아니에요.

예보 모델이 같은 조건을 여러 번 시뮬레이션했을 때 10번 중 6번꼴로 비가 내렸다는 의미에 가깝습니다. 그래서 강수확률이 높아도 실제로 안 올 수 있고, 낮아도 소나기가 올 수 있어요. 수업에서 ‘확률’과 ‘실제 관측’의 차이를 이야기하기 좋은 소재입니다.
💡 변수 바꾸는 법 — 주소의 hourly= 뒤만 고치면 끝
앞서 만든 코드에서 요청 주소의 hourly= 뒤만 바꾸면 다른 데이터를 받습니다.
· 기온: ...&hourly=temperature_2m
· 자외선 지수: ...&hourly=uv_index
· 일사량(태양광): ...&hourly=shortwave_radiation
여러 개를 쉼표로: ...&hourly=temperature_2m,relative_humidity_2m
과거 데이터는 주소를 https://archive-api.open-meteo.com/v1/archive 로 바꾸고 &start_date=2015-06-01&end_date=2015-06-30 처럼.

CHAPTER 04

MQ-2 가스센서 대시보드

공기 중 가스를 숫자로 읽고, 안전/주의/위험을 색과 그래프로 보여 주는 다크 테마 대시보드를 만듭니다.

🎯 이 장을 마치면
  • ADC로 가스센서 값을 읽고 전압·비율로 바꿀 수 있다
  • 이동 평균으로 값을 안정시킬 수 있다
  • 임계값으로 안전/주의/위험 상태를 판단해 웹으로 보여 준다
💡 왜 배우나요?

공기질은 눈에 안 보이죠. MQ-2 센서로 측정해 숫자 → 색 → 그래프로 바꾸면, 환기 타이밍을 한눈에 알 수 있어요. 센서값을 ‘판단(임계값)’하고 피코가 웹서버가 되어 ‘예쁜 화면’으로 보여 주는, 가장 완성도 높은 대시보드입니다.

핵심 개념

ADC (아날로그)
가스 농도 같은 ‘연속된 값’을 숫자로 바꿔 읽는 기능. 그로브 A0 = GP26. ADC(Pin(26))
read_u16()
0~65535 사이 값으로 읽습니다. 가스가 짙을수록 값이 커져요.
이동 평균
여러 번 읽어 평균 내면 값이 출렁이지 않고 안정됩니다. read_average()
임계값
SAFE / WARNING / DANGER를 나누는 기준 숫자. 환경마다 달라 보정이 필요해요.
🔬 더 알아보기 — ADC가 ‘전압’을 ‘숫자’로 바꾸는 원리 (볼트 변환)
센서는 가스 농도를 전압(아날로그)으로 내보냅니다. 0V~3.3V 사이의 ‘연속된’ 값이죠. 그런데 컴퓨터는 숫자만 다루니, 이 전압을 숫자로 바꿔야 합니다. 그 변환기가 ADC(Analog-to-Digital Converter, 아날로그→디지털 변환기)예요.

피코의 ADC는 16비트 해상도로 읽습니다. 16비트 = 2¹⁶ = 65536단계, 그래서 read_u16()은 0 ~ 65535 사이 숫자를 돌려줘요.
· 0V → 0
· 3.3V(최대) → 65535
· 그 사이는 비례. 따라서 숫자를 전압으로 되돌리면:
전압(V) = read_u16() / 65535 × 3.3

예) 읽은 값이 32768이면 → 32768/65535×3.3 ≈ 1.65V (딱 절반).

주의: MQ-2에서 ‘전압이 곧 가스 농도(ppm)’는 아닙니다. 정확한 ppm은 보정·계산이 필요해서, 수업에서는 상대적인 변화(평소보다 높다/낮다)를 보는 지표로 씁니다. 그래서 SAFE/WARNING/DANGER 임계값도 우리 교실에서 직접 보고 정합니다.
ℹ️ 센서는 예열이 필요해요
MQ-2는 전원을 넣고 1~2분 지나야 값이 안정됩니다. 처음 켜자마자 값이 크게 나와도 놀라지 마세요.
ℹ️ 먼저 — 와이파이 정보 파일 만들기 (wifi_config.py)
대시보드 코드는 와이파이 정보를 wifi_config.py에서 불러옵니다. main.py와 같은 위치에 이 파일을 새로 만들고 두 줄만 적어 저장하세요.

def read_average(sensor, count=10):
    total = 0
    for _ in range(count):
        total += sensor.read_u16()
        time.sleep_ms(10)
    return total // count


def connect_wifi():

def send_response(conn, status, content_type, body_bytes):
    header = (
        f"HTTP/1.1 {status}\r\n"
        f"Content-Type: {content_type}\r\n"
        f"Content-Length: {len(body_bytes)}\r\n"
        "Access-Control-Allow-Origin: *\r\n"
        "Connection: close\r\n"
        "\r\n"
    ).encode()
    conn.sendall(header + body_bytes)


def run_server():
    addr = socket.getaddrinfo("0.0.0.0", 80)[0][-1]
    srv  = socket.socket()
    srv.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    srv.bind(addr)
    srv.listen(3)
    print("서버 대기 중... (Ctrl+C로 종료)")

프로젝트에 쓸 만한 과목별 오픈 API 카탈로그예요. 각 API가 어떤 데이터를 주고 무엇을 탐구할 수 있는지 보고, 바로 살아 있는 대시보드로 들어가 보세요.

💡 왜 배우나요?

3장에서 API로 데이터를 받아 표현하는 흐름을 익혔죠. 이 부록은 과목별 오픈 API를 한눈에 정리한 카탈로그예요 — 각 API가 어떤 데이터를 주고 어떤 탐구를 할 수 있는지, 그리고 브라우저에서 바로 그려 보는 라이브 대시보드로 연결됩니다. 피코로 직접 받아오려면 3장 ‘날씨 시계’에서 쓴 socket+ssl 방식을 그대로 응용하면 돼요. (API는 2026년 기준 응답 확인)
